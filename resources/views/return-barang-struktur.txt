syarat dan ketentuan bisnis rule untuk return barang pembangunan unit #Table

Tujuan
    Fitur ini digunakan untuk mengembalikan material proyek yang sudah pernah diambil dari gudang.
    Return dilakukan berdasarkan Pembangunan Unit + QC, bukan berdasarkan Order Barang.
    Return hanya dapat dilakukan terhadap barang yang benar-benar pernah di-ACC oleh gudang.

Syarat Return Barang
1. Return Berdasarkan QC
    Setiap return harus berasal dari: pembangunan unit + QC
        contoh: Unit A > QC 1  Pondasi
        Return pondasi tidak boleh di gabung dengan return QC 2 (Dinding)
    
2. Return tidak berdasarkan order
    misalnya: Order 1 -> semen 4 sak
              Order 2 -> Semen 3 Sak
    Pengawas tidak pernah memilih Order 1 atau Order 2 untuk return barang, yang ditampilkan hanya
        -> Semen - Total diterima: 7 Sak | Sudah return: 2 Sak | Sisa Return: 5 sak
    Pengawas cukup menentukan jumlah yang dikembalikan.
    
3. Barang yang dapat direturn
    Barang hanya muncul apabila
       - Status order = selesai && Konfirmasi = true
    Artinya: Barang sudah benar benar keluar dari gudang.

4. Maksimal Return 
    Maksimal return dihitung >> Total Order ACC - Total Return
    Contoh: Order 1 -> 10 sak Semen
            Return 1 -> 2 sak Semen
            Maksimal Return -> 8 sak Semen

5. Satuan return 
    Pengawas boleh memilih satuan.
        Contoh: Keramik Kamar mandi > 4 Dus atau 16 Pcs
    kemudian sistem mengubah menjadi jumlah_base menggunakan barang_satuan_konversi sehingga seluruf validasi menggunkan jumlah_base

6. Status Return
    -> Draft (Return masih bisa diedit)
    -> DiProses (Sudah dikirim ke gudang & belum mempengaruhi data apapun)
    -> Selesai (Gudang sudah menerima barang dan kualifikasi barang itu menjadi barang layak dan rusak)
    -> Ditolak (Gudang menolak return barang, ketika tidak ada barang yang direturn dilapangan)
    
KETENTUAN SAAT PENGAWAS UNIT SUBMIT RETURN
=> ketika status menjadi (diproses)
    sistem hanya menyimpan: 
        - header return
        - detail return 
        - belum terjadi
            ❌ Penambahan Stock Gudang
            ❌ Stock Ledger
            ❌ Nota Barang Masuk RTN
            ❌ Pengurangan Termin
            ❌ Update jumlah_return_base
            Semua masih menunggu ACC Gudang.

=> Ketentuan Penolakaran Return barang
    Jika gudang memilih Tolak, status menjadi ditolak mengisi alasan tolak.
    tidak ada perubahaan: order detail, termin, stock gudang, stock ledger, nota RTN

=> Prinsip fifo
    FIFO hanya digunakan oleh Backend.
    Pengawas tidak pernah mengetahui Order pertama, order kedua atau nota barang masuk. 
    FIFO hanya bertugas menentukan Order Detail mana yang harus dikurangi.

=> Prinsip Harga
    Harga return selalu menggunakan harga_satuan_snapshot milik order_detail
    bukan harga terbaru dan bukan mengambil ulang fifo dari nota barang masuk. Karena harga sudah dibekukan saat order di-ACC

=> Prinsip Termin 
    nilai pembangunan_unit_bahan selalu mencerminkan barang yang benar benar dipakai proyek, oleh karena itu setiap return 
    baik layak maupun rusak tetap mengurangi jumlah_pakai && harga_total_snapshot



A. BUSINESS RULE ORDER BARANG

    1. Pengajuan Barang
        Pengawas membuat permintaan barang berdasarkan Pembangunan Unit + QC
        Setiap order hanya boleh berasal dari satu QC.
        Contoh: Unit A
                QC Pondasi
                
    2. Jenis Order 
        Order terdiri dari stock / direct Barang Stock dan Direct tidak boleh dicampur dalam satu order.
    
    3. Status order
        Diproses (Gudang belum acc)
        Selesai (Gudang sudah acc)
    
    Ketentuan ACC GUDANG ORDER
        Saat Gudang menekan tombol ACC seluruh proses dilakukan dalam satu Database Transaction.

    Langkah 1
        Validasi: 
            - stok mencukupi
            - barang masih aktif
            - order belum pernah di ACC
        Jika gagal
            - Rollback. 
    
    Langkah 2
        FIFO Pengeluaran
        - Backend mengambil Nota Barang Masuk berdasarkan FIFO.
        Contoh:
            - Nota A ->5 Sak
            - Nota B ->3 Sak

            - Order ->7 Sak
        backend mengambil: 
            5 dari nota a & 2 dari nota b
    
    Langkah 3
        Update Nota Barang Masuk
    Mengurangi jumlah_sisa
            pada setiap layer FIFO yang digunakan.
    
    Langkah 4
        Membuat FIFO Usage
            Untuk setiap layer FIFO yang dipakai dibuat mapping (pembangunan_unit_barang_fifo_usage)
        contoh: 
            order detail   | nota     | pakai 
            20             | nota A   | 5
            20             | nota B   | 2
        table ini menjadi history permanen asal barang keluar. 

    Langkah 5
        Mengurangi Stock Gudang
            Stock Gudang dikurangi sesuai jumlah yang keluar.
    
    Langkah 6 
        Membuat Stock Ledger
            Tipe Keluar
            menggunakan snapshot harga FIFO.
    
    Langkah 7 
        Update Order Detail
            Mengisi:  konfirmasi, harga_satuan_snapshot, harga_total_snapshot
            
    Langkah 8
        Update termin 
            menambah pembangunan_unit_bahan, karena material sekarang dianggap telah digunakan proyek
    
    Langkah 9 
        Update status order
            status menjadi selesai

B. BUSINESS RULE RETURN BARANG
    Tujuan
        Return digunakan untuk mengembalikan material proyek yang tidak terpakai.
        Return dilakukan berdasarkan = Pembangunan Unit + QC
        bukan berdasarkan Order Barang.

    Ketentuan ACC GUDANG RETURN 
        Seluruh proses dilakukan dalam satu database transaction.
    
    Langkah 1
        validasi 
        Jumlah Return tidak boleh melebihi = Total acc - total return 

    Langkah 2 
        FIFO Return
        Backend mencari (pembangunan_unit_barang_fifo_usage) yang masih memiliki jumlah_base > jumlah_return_base
        berdasarkan FIFO pemakaian.
        Backend membuat mapping (pembangunan_unit_barang_return_fifo)
        Pengawas tidak mengetahui proses ini.

    Langkah 3 
        Update fifo usage
        untuk setiap mapping jumlah_return_base ditambah sesuai qty return. 
        Dengan demikian setiap layer FIFO mengetahui berapa yang sudah dikembalikan.
    
    Langkah 4
        Update order detail 
        Order Detail yang terkait ikut diperbarui jumlah_return & jumlah_return_base

    Langkah 5
        Kurangi Termin
        Mengurangi = jumlah_pakai & harga_total_snapshot pada (pembangunan_unit_bahan)

    Langkah 6
        Input Pemeriksaan Gudang
        Gudang menentukan: Layak / Rusak
        Harus memenuhi = layak + rusak = total return
    
    Langkah 7 
        Barang Layak
        Jika    
            jumlah_layak_base > 0
        maka
            Membuat Nota Barang Masuk RTN
            Supplier Return Internal
            Status Posted
            Menambah Stock Gudang ke ubs mangoon
            Membuat Stock Ledger Masuk

    Langkah 8
        Barang Rusak
        Jika
            jumlah_rusak_base > 0
        Maka
            Tidak membuat Nota RTN
            Tidak menambah Stock Gudang
            Diproses pada Modul Barang Rusak
        Namun Termin tetap berkurang.

    Langkah 9
        Update status return
        Status menjadi selesai && 
        mengisi acc_by & acc_at
